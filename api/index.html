    API reference

    Intermediate representation

    Solver-neutral intermediate representation (IR) of a linear / mixed-integer model.

    Every model in this package is compiled to the canonical form

    .. math::

    \min_x / \max_x \; c^\top x + c_0
\quad\text{s.t.}\quad A x \;\{\le, =, \ge\}\; b,
\quad \ell \le x \le u,
\quad x_j \in \mathbb{Z} \;\; (j \in \mathcal{I}).

    Problems never talk to a solver directly. They declare blocks of variables and constraints through :class:ModelBuilder; each backend (Gurobi, HiGHS) translates the resulting :class:LinearModel with its native matrix API. Blocks keep the algebra readable: a transport model has one flow block of shape (m, n) and constraint blocks supply and demand, and solution values or duals are read back by block rather than by raw index.

    ConstrBlock dataclass

    A named, contiguous block of constraints sharing one sense.

    slice property

    Position of the block in the global constraint vector.

    values(y)

    Extract this block's entries (e.g. duals) from a global vector.

    LinearModel dataclass

    Immutable, validated model in canonical matrix form. Build via :class:ModelBuilder.

    integer_mask property

    Boolean mask of integer or binary columns.

    is_mip property

    Whether any variable is integer or binary.

    num_constrs property

    Number of rows.

    num_nonzeros property

    Non-zeros in the constraint matrix.

    num_vars property

    Number of columns.

    constr_names()

    Readable row names such as demand[12] (cached).

    relaxed()

    Continuous (LP) relaxation: same model with every integrality dropped.

    Binary bounds are already [0, 1], so only the variable types change.

    stats()

    Size statistics, e.g. to check against the restricted Gurobi licence.

    var_names()

    Readable column names such as flow[3,7] (cached).

    with_cuts(cuts, name='cuts')

    A copy with extra rows appended as one constraint block name.

    cuts are :class:~linear_opt.core.result.Cut objects (cols, coefs, sense, rhs). Used for row generation.

    ModelBuilder

    Incrementally declare variable and constraint blocks, then :meth:build.

    Example

    b = ModelBuilder("toy", ObjSense.MAXIMIZE) x = b.add_vars("x", 2, obj=[3.0, 5.0]) _ = b.add_constrs("cap", [(x, [[1, 0], [0, 2], [3, 2]])], Sense.LE, [4, 12, 18]) b.build().num_constrs 3

    sum_over(shape, axis)

    Matrix that sums a row-major (m, n) block along axis.

    Models and results

    Base class for every optimisation model: build -> solve -> extract -> validate.

    OptimizationModel

    Bases: ABC, Generic[D, S, O]

    Template for a problem class.

    Subclasses implement three things:

    • :meth:_build - declare variables/constraints on a :class:ModelBuilder;
    • :meth:_extract - turn the raw vector into a typed, domain-level solution;
    • :meth:validate - re-check feasibility from the instance data, so a modelling bug cannot hide behind a solver reporting "optimal".

    Optional hooks: :meth:lazy_constraints and :meth:warm_start.

    Compile (once) to the solver-neutral IR.

    RawSolution dataclass

    What a backend returns: status, primal/dual vectors and statistics.

    Dual sign convention (shared by Gurobi and HiGHS, checked in the tests): for a minimisation, duals of >= rows are non-negative and of <= rows non-positive; signs flip for maximisation. Reduced costs are c - A^T y.

    gap property

    Relative optimality gap |obj - bound| / max(|obj|, 1e-10).

    has_solution property

    Whether a feasible primal solution is available.

    SolveStatus

    Bases: StrEnum

    Termination status, harmonised across backends.

    LP duality checks: an independent certificate of optimality.

    For a primal-dual pair :math:(x^*, y^*) with reduced costs :math:z = c - A^\top y, the Lagrangian dual objective is

    .. math::

    g(y) = c_0 + b^\top y + \sum_j z_j \cdot
    \begin{cases} \ell_j & z_j > 0 \\ u_j & z_j < 0 \end{cases}
\qquad (\text{minimisation; bounds swap for maximisation}).

    Strong duality says :math:g(y^*) = c^\top x^* + c_0. Checking it, plus the sign conditions on :math:y, verifies a solver's answer without trusting it.

    dual_objective(model, y, tol=1e-09)

    Lagrangian dual objective g(y); -inf/+inf if y is dual infeasible.

    dual_sign_violations(model, y, tol=1e-07)

    Rows whose dual has the wrong sign for the row sense.

    duality_gap(model, primal_objective, y)

    Relative gap between primal objective and dual objective.

    SolverBackend

    Bases: ABC

    Translate a :class:LinearModel, solve it, and harmonise the result.

    Every backend accepts a lazy-constraint oracle. Backends with :attr:Capability.LAZY_IN_TREE call it inside branch-and-bound; the others fall back to row generation (solve, separate, add cuts, re-solve), which is slower but returns the same optimum.

    solve_by_row_generation(solve, model, settings, oracle, max_rounds=10000)

    Solve, separate, add violated cuts, re-solve - until none is violated.

    Works for LPs and MIPs on any backend. Returned duals cover the original rows only.

    Gurobi backend built on the gurobipy matrix API.

    Showcases:

    • addMVar / addMConstr - one call per block, no Python loops over variables;
    • a callback that (a) adds lazy constraints at integer-feasible nodes via cbLazy and (b) records the incumbent / bound trajectory;
    • MIP starts through MVar.Start;
    • IIS computation for infeasible models;
    • a clean mapping of the size-restricted pip licence error to :class:LicenseLimitError.

    GurobiBackend

    Bases: SolverBackend

    Gurobi via gurobipy (works with the bundled restricted licence).

    compute_iis(model, settings)

    Return names of constraints and bounds forming an IIS (empty if feasible).

    write_model(model, path)

    Write the model with Gurobi's writer (.lp, .mps, ...).

    HiGHS backend (open source, MIT licence) via highspy.

    The model is passed in one shot as a column-wise HighsLp. Lazy constraints are handled by row generation: solve, ask the oracle for violated cuts, append them with addRow and re-solve until no cut is violated. This gives the same optimum as in-tree lazy constraints, at the price of re-solving.
